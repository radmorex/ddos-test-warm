# 🐝 LoadSwarm — роевое нагрузочное тестирование своих серверов

Распределённый генератор нагрузки: один **контроллер** (на VPS) + **агенты** на всех
ваших машинах (Windows / macOS / Linux). Агенты подключаются к контроллеру
**исходящими** соединениями, забирают задачу и генерируют HTTP-нагрузку.
Проброс портов и белые IP для агентов не нужны.

## ⚠️ Правила

1. Тестируйте **только серверы, которыми вы владеете** (или есть письменное разрешение).
2. Сервер у хостинг-провайдера? Проверьте его правила: у многих stress-тесты
   запрещены или требуют уведомления.
3. Начинайте с малого (суммарно ≤ 50 виртуальных пользователей) и наращивайте плавно.
4. Не запускайте агентов на умных устройствах/бытовухе — только компьютеры.
5. Нужен Python **3.9+**.

## Архитектура

```
                    ┌────────────────────────── VPS ──────────────────────────┐
                    │  controller.py  :8080  (доска задач + дашборд)          │
                    └───────▲──────────────▲──────────────▲───────────────────┘
                            │  poll job    │  poll job    │   (исходящие
        ┌───────────────────┴──┐    ┌──────┴─────────┐  ┌─┴────────────────┐ соединения
        │ агент: Windows ПК    │    │ агент: macOS   │  │ агент: Linux-box │  агентов)
        └──────────────────────┘    └────────────────┘  └──────────────────┘
```

## 1. Контроллер (на VPS)

```bash
cd loadswarm
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
LOADSWARM_TOKEN=$(openssl rand -hex 16) .venv/bin/python controller.py --port 8080
```

Скопируйте напечатанный токен. Откройте `http://<IP-vey-VPS>:8080/`, введите токен.

Автозапуск: `scripts/loadswarm-controller.service` (systemd, инструкция в шапке файла).

## 2. Агенты (на каждой машине)

### Быстрее всего: файл подключения (macOS / Windows)

Откройте дашборд, раздел **«Добавить агента»**, и скачайте готовый файл — адрес
контроллера и токен уже вшиты:

- **macOS:** `join.command` — откройте двойным кликом (если Gatekeeper спросит —
  подтвердите). Terminal сам скачает агента, создаст venv, поставит aiohttp,
  пропишет автозапуск (launchd) и запустит агента; окно не закроется, пока
  не нажмёте Enter.
- **Windows:** `join.bat` — откройте двойным кликом; дальше всё делает
  PowerShell-инсталлятор: агент, aiohttp, автозапуск (планировщик/автозагрузка).

Через ~10 секунд машина появится на дашборде в статусе «простой».

> Файл содержит токен контроллера — запускайте его только на своих машинах.

### Или одна команда (Linux, SSH, автоматизация)

Там же в разделе готовые команды с уже вшитым токеном — скопируйте и выполните
на новой машине:

- **macOS / Linux:**
  ```bash
  curl -fsSL "http://<IP-VPS>:8080/install.sh?token=<ТОКЕН>" | sh
  ```
- **Windows (PowerShell или cmd):**
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -Command "irm 'http://<IP-VPS>:8080/install.ps1?token=<ТОКЕН>' | iex"
  ```

То же самое, что и файл подключения: скачивает `agent.py`, ставит aiohttp,
прописывает автозапуск (launchd / systemd / планировщик) и запускает агента —
удобно по SSH и в скриптах. Своё имя агента — добавьте `&name=<ИМЯ>` к ссылке
(для файлов подключения это делается параметром `name` в ссылке скачивания).

> Команда содержит токен — запускайте её только на своих машинах.

### Вручную

```bash
pip install aiohttp
python3 agent.py --controller http://<IP-VPS>:8080 --token <ТОКЕН> --name mac-mini
```

- **Windows**: сначала `pip install aiohttp`, затем та же команда
  (`python agent.py --controller ... --token ... --name win-pc`).
- Автозапуск: `scripts/loadswarm-agent.service` (Linux/systemd),
  `scripts/com.loadswarm.agent.plist` (macOS/launchd),
  `scripts/install-agent-windows.ps1` (Windows, планировщик задач).

Агент появится на дашборде со статусом «простой» и будет ждать задачу.

## 3. Тест

На дашборде нажмите **«▶ Запустить нагрузку»** — откроется окно задачи:

- URL и метод своего сервера, тело и заголовки (опционально);
- **concurrency на агента** — виртуальные пользователи с каждой машины;
- **разгон ramp-up, с** — сколько секунд наращивать число активных воркеров
  от 0 до заданного (0 = мгновенный старт);
- длительность и таймаут;
- **чекбоксы агентов** — нагрузку дают только отмеченные; ничего не отмечено = все;
- **пресеты** — текущую конфигурацию можно сохранить под именем (💾) и загрузить
  из списка в следующий раз; хранятся в `presets.json` рядом с `controller.py`
  и переживают перезапуск контроллера;
- в «Завершённых задачах» кнопка **«повторить»** открывает окно, заполненное
  параметрами той задачи — включая ramp-up, тело и заголовки.

Внизу окна — оценка: «итого: N агентов × concurrency = M виртуальных
пользователей». После «▶ запустить» агенты подхватят задачу в течение ~3 секунд.
Остановить — кнопка «■ остановить» на дашборде.

Нюансы:
- **Итого виртуальных пользователей = concurrency × число выбранных агентов** (10 × 5 машин = 50).
- Ramp-up размазывает старт: воркер i начинает через rampup × i / concurrency
  секунд, пик нагрузки достигается плавно — щадяще для слабых машин и для таргета.
- Каждый воркер агента делает запросы непрерывным циклом (closed-loop).
- 2xx–3xx = успех; 4xx, 5xx, таймауты, обрывы = ошибки (разбивка по кодам в статистике).
- Длительный тест: на дашборде RPS и латентности обновляются каждые 2 с.
- Во время теста строятся графики: RPS (ok/err) и латентность (avg/p95/p99) по секундам.
- Если таргет недоступен (обрывы, RST), агент сам сбрасывает темп — не больше 100
  неудачных соединений в секунду. Без этого рой устраивает шторм из тысяч коннектов,
  на который ядро macOS отвечает троттлингом новых соединений (`net.inet.tcp.rst_rlc`),
  и даже живой таргет после такого шторма подвисает на несколько секунд.

## Безопасность

- Все API-эндпоинты и дашборд закрыты токеном (`LOADSWARM_TOKEN`).
- Контроллер слушает `0.0.0.0:8080`. На публичном VPS:
  - ограничите порт фаерволом (только ваш IP), **или**
  - поставьте [Tailscale](https://tailscale.com) на VPS и все машины с агентами —
    тогда контроллер можно запускать как `--host <tailscale-IP>`, и наружу не
    светится вообще ничего (рекомендуется), **или**
  - поставьте nginx/caddy с HTTPS перед контроллером.
- Токен один общий; состояние хранится в памяти (перезапуск контроллера не страшен —
  агенты перерегистрируются автоматически).
- Файлы подключения (`join.command`, `join.bat`) и команды установки содержат
  токен — не пересылайте их за пределы своих машин.

## Файлы

| Файл | Назначение |
|---|---|
| `controller.py` | контроллер: доска задач, приём статистики, дашборд с графиками, окно запуска (выбор агентов, ramp-up, пресеты), раздача `agent.py`, генерация инсталляторов и файлов подключения (`/install.sh`, `/install.ps1`, `/join.command`, `/join.bat`), CRUD пресетов (`/api/presets`) |
| `agent.py` | агент: poll задач, генерация нагрузки (closed-loop, ramp-up, предохранитель от шторма коннектов), отчёт раз в секунду |
| `presets.json` | (создаётся контроллером) сохранённые пресеты конфигураций задач |
| `requirements.txt` | зависимости (fastapi, uvicorn — контроллер; aiohttp — агент) |
| `scripts/` | автозапуск: systemd ×2, launchd, планировщик Windows |
